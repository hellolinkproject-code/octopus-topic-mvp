# 미션 8 멘토 피드백 반영

검토일: 2026-09-28

## 반영한 제안

### 1. 외부 연결 실패와 타임아웃 구분

`fetch`의 모든 예외를 `AI_TIMEOUT`으로 처리하던 코드를 변경했다.

| 예외 | HTTP 상태 | 오류 코드 | 사용자 안내 |
| --- | --- | --- | --- |
| `TimeoutError`, `AbortError` | 504 | `AI_TIMEOUT` | 연결 지연 후 재시도 안내 |
| DNS·TLS 등 나머지 연결 예외 | 503 | `AI_UNREACHABLE` | 서비스에 연결하지 못했다는 안내 |

현재 서버 호출에는 시간 제한 신호만 연결되어 있다. 향후 사용자 취소 신호를 추가하면 `AbortError`도 취소 사유에 맞게 별도 분류해야 한다. 제공자가 HTTP 오류 응답을 반환한 경우의 `AI_UNAVAILABLE` 처리는 유지한다.

타임아웃, 중단, DNS 실패, TLS 실패를 모의해 실제 첨삭 API 핸들러의 상태·코드를 검증한다. 각 경우에 포인트 유지, 작업 예약 해제, 결과 미저장, 재시도 성공도 확인한다. 운영 서버의 DNS·TLS 장애를 의도적으로 발생시키지는 않는다.

연결 실패 로그에는 고정된 오류 코드와 HTTP 상태만 남긴다. 원본 예외·원인 객체·답안·자격 증명을 기록하지 않는 것도 테스트로 확인한다.

### 2. 로딩부터 완료까지 유지되는 상태 안내

`FeedbackPanel`의 결과/요청 분기 밖에 `role="status" aria-atomic="true"` 영역을 두었다. 요청 전에는 비어 있고, 처리 중에는 대기 문구, 결과가 도착하면 저장 완료 문구로 바뀐다. 결과가 먼저 컨텍스트에 반영되고 요청 Promise가 나중에 종료되어도 완료 문구를 우선한다.

결과 본문에 붙었던 `aria-live`는 제거했다. 시각적인 대기 문구는 유지하되 중복 낭독을 피하도록 접근성 트리에서 제외했다. 한국어 결과의 `lang="ko"`는 유지했다.

회귀 테스트는 요청 전·로딩 중·완료 후에 **동일한 DOM 상태 영역**이 유지되고, 완료 문구가 바뀌며 상태 영역이 하나뿐인지 확인한다. 이는 DOM 구조 검증이며 실제 스크린 리더 음성 출력 검증과는 구분한다.

## 이번에는 추가하지 않은 제안: 미결제 첨삭 보관

문제의식은 타당하지만 현재 서비스에서는 다음 조건을 확인했다.

1. 포인트를 차감하는 API는 54번 첨삭뿐이다. 퀴즈와 53번은 적립, 54번 저장은 무료다.
2. 작업 예약은 답안별이 아니라 **사용자 전체에서 1건**이다. 다른 탭에서 다른 54번 답안을 요청해도 `FEEDBACK_BUSY`로 거절한다.
3. 조건부 쓰기로 예약과 최종 저장을 검증하며, 최종 저장에서는 같은 작업 ID인지 다시 확인한다.

따라서 현재 지원되는 API만 이용할 때 첨삭 생성 중 다른 정상 소비가 끼어들어 잔액을 줄이는 경로는 없다. 동일 답안뿐 아니라 다른 답안의 동시 요청도 외부 호출 전에 차단한다는 회귀 검증을 추가했다.

미결제 상태는 필드 하나를 추가하는 것으로 끝나지 않는다. 결과 공개 범위, 재조회 권한, 후속 정산과 중복 차감 방지, 포인트 사용 안내까지 함께 정해야 한다. 이번 MVP에서는 **성공적으로 저장한 첨삭은 50P, 저장 실패 시 차감 없음**이라는 기존 정책을 유지한다. 방어적 잔액 검사도 유지하며, 비정상적인 잔액 변경으로 이 검사에 걸리면 결과를 저장하지 않고 예약을 해제한다. 일일 한도는 실제 외부 호출 시도를 기준으로 하므로 자동 복구하지 않는다.

### 이후 다른 포인트 소비 기능을 추가할 때의 조건

- 모든 차감 경로에서 진행 중인 첨삭의 예약 금액을 사용하지 못하게 해야 한다.
- 여러 종류의 소비를 허용한다면 공통 포인트 원장과 예약·확정·해제 처리를 먼저 설계한다.
- 미결제 결과 보관을 선택한다면 API 공개 범위와 정산 UI를 함께 구현한다. `unpaid` 표시만 추가하고 결과를 기존 무료 재조회 경로에 그대로 반환하지 않는다.
- 외부 AI 호출과 저장소 쓰기는 분산 트랜잭션이 아니므로, 저장 장애로 제공자 호출 비용만 발생하는 한계는 여전히 존재한다.

## 검증 기록

- 전체 자동 테스트: **14개 파일, 84개 테스트 통과**.
- 포맷 검사, 프로덕션 빌드, `git diff --check` 통과.
- 오류 분류·로그·포인트 보존은 모의 외부 응답으로 확인했다. 운영 환경의 장애를 고의로 유발하지 않았다.
- 상태 안내의 DOM 유지와 완료 문구 전환은 컴포넌트 테스트로 확인했다. 실제 스크린 리더 음성 출력은 별도 수동 검증 범위다.
